TEST AKIŞI
===========

[A] Vardiya kapalıyken kasaya gir:
    1. Demo kafede kasiyer girişi yap
    2. ✅ Üstte BÜYÜK KIRMIZI BANT görmeli:
       "⚠ VARDİYA KAPALI · SATIŞ ALINAMIYOR"
       "VARDİYA AÇ →" butonu
    3. Boş masaya tıkla
    4. ✅ Toast: "Kasa kapalı - önce Kasa sekmesinden kasayı aç"
    5. Hızlı satış sekmesi → "+ Yeni Satış" butonu disabled

[B] Vardiya başlat:
    1. "VARDİYA AÇ →" tıkla
    2. CashSessionModal açıldı, mode='open'
    3. "Başlangıç tutarı" alanını BOŞ bırak, "Aç" tıkla
    4. ✅ Hata: "Başlangıç tutarı zorunlu. Kasada hiç para yoksa 0 yaz."
    5. "0" yaz, Aç tıkla
    6. ✅ Vardiya açıldı, kırmızı bant kayboldu
    7. Masa tıkla → composer açılır → sipariş kaydedilir

[C] Backend savunma testi (frontend bypass etse bile):
    1. Vardiyayı kapat (RegisterPanel'den "Gün Sonu" wizard)
    2. Frontend cache eski state tutarsa → masaya tıklayıp sipariş gönderse bile
    3. ✅ Backend: { success: false, error: "Vardiya kapalı. Satış almak için..." }

[D] Garson siparişi vardiya kapalıyken (MUAF):
    1. Vardiya kapalı
    2. /garson sayfasına gir, PIN ile login
    3. Masa seç → ürün ekle → "Sipariş Gönder"
    4. ✅ Sipariş başarıyla gönderildi (garson source='waiter' geçiyor)
    5. Sipariş orders tablosunda görünür
    6. Kasada görünür ama ÖDENEMEZ → "Vardiya kapalı" hatası
    7. Önce vardiya açılır, sonra ödeme alınır → ✓

[E] Düzeltici işlemler vardiya kapalıyken:
    1. Önceden ödenmiş bir siparişe ikram uygulamak istiyorsun
    2. Tümü ikram (giftAll) → ✅ çalışır
    3. Tek kalem iptal → ✅ çalışır
    4. Masa taşı → ✅ çalışır
    (Bu işlemler vardiyaya bağlanmıyor, düzeltme amaçlı)

NOTLAR
=======

⚠ source='waiter' parametresi yeni eklendi. Garson çağrısı güncellendi.
   Eğer eski offline cache'te source'suz garson siparişi varsa,
   sync sırasında SERT kontrole takılabilir → manual sayılır.
   Bu durumda offline cache'i temizletmek gerekebilir (rare edge case).

⚠ Düzeltici işlemler (cancelOrderItems, makeItemsComplimentary,
   changeOrderTable, splitOrderItems, mergeTables) vardiya kontrolü
   ALMADI bilinçli olarak — gece gelen şikayetlerde vardiya açılmadan
   düzeltme yapılabilir. Eğer iş süreçleri farklı, isteğe bağlı eklenir.

⚠ Bu sprint takePayment'ı korur. closeOrderOnAccount (cari hesaba yaz)
   ayrı bir akış — şu an kontrol yok. İşletme veresiyeye yazıp ödemeyi
   sonra alıyorsa zaten ödeme adımında kontrol var. Yine de istersen
   eklenebilir.
