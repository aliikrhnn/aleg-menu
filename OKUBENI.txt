✱ AKIŞ
──────
1. /admin/isletmeler/{id} → Ayarlar tab → "Tehlikeli Bölge"
2. "İşletmeyi Sil" → preflight kontrol (anlık veri sayımı)
3. Karşı ekranda görünen:
   - Üye / Ürün / Toplam sipariş / Cari bakiye sayıları
   - RİSK varsa altın uyarı kutusu (ödenmemiş sipariş, açık kasa,
     pozitif cari bakiye)
   - "Riskleri biliyorum, yine de sil" toggle
   - "Onaylamak için adı yaz" inputu (tam eşleşme)
4. Adı doğru yaz + onay → kalıcı silme
5. CASCADE: tüm alt veriler (orders, products, members, vs.) silinir
6. Sahibi başka işletmenin sahibi/üyesi DEĞİLSE auth user da silinir
7. platform_audit_logs'a 'business.deleted' kaydı atılır

✱ KORUMALAR
────────────
🛡 PREFLIGHT — kazara silmeyi önler:
   - Ödenmemiş aktif sipariş varsa
   - Açık kasa oturumu (kapatılmamış vardiya) varsa
   - Cari bakiye pozitifse (tahsil edilmemiş para)
   → Süper admin "Riskleri biliyorum" kutusunu işaretlemeden silemez

🛡 AD YAZMA ONAYI — yanlış işletme silmeyi önler:
   - İşletme adı tam yazılmadan "Kalıcı Sil" butonu disabled
   - Case-sensitive (büyük/küçük harf önemli)

🛡 MULTI-TENANT SAFE — sahibi başka kafelerin de sahibi/üyesi ise
   auth user'ı SİLMEZ:
   - Mesela aynı kişi 2 kafenin sahibi → birini silersen
     diğerine girişi devam eder
   - businesses tablosunda owner_user_id veya
     business_members'ta user_id kontrolü yapılır

🛡 AUDIT LOG — silme işlemi platform_audit_logs'a yazılır:
   - actor_id (kim sildi), actor_email
   - target_type='business', target_id (silindi ama UUID kalır),
     target_label (işletme adı snapshot)
   - meta: { slug, product_count, total_order_count, forced,
            auth_user_deleted, owner_user_id }
   - tone='danger'
   - business_id null çünkü silindi (ON DELETE SET NULL'a düşmesin)

✱ EDGE CASES İLE İLGİLİ NOT
───────────────────────────
• Sahibi 2 kafenin de sahibi:
  → 1. kafeyi sildin → auth user silinmez (diğerine girişi var)
  → 2. kafeyi de sildin → auth user silinir (artık hiçbir yere
    bağlı değil)

• Sahibi başka kafenin sadece üyesi (business_members):
  → İşletme silinince auth user silinmez

• Silme sırasında database hatası:
  → audit log'a 'business.delete_failed' kaydı atılır,
    error mesajı kullanıcıya gösterilir, business korunur

• Subdomain (Vercel) silme YOK — manuel:
  → Sildikten sonra Vercel dashboard'a git, Domains → ilgili
    subdomain'i remove et (yoksa boş slug için 404 dönmeye devam eder)
