═══ 1. SENTRY ERROR TRACKING ═══

Production'da bir yer patlarsa kim bilecek? Şimdi:
  - User'da JS hatası → Sentry'e gider, replay video ile
  - Server action hatası → Sentry'e gider, request bilgisi ile
  - Edge/middleware hatası → Sentry'e gider
  - Global error fallback ekranı (kullanıcıya hoş bir mesaj)

Yapılan değişiklikler:
  - sentry.client.config.ts (yeni) — Browser-side Sentry
  - sentry.server.config.ts (yeni) — Server actions için
  - sentry.edge.config.ts (yeni) — Middleware için
  - instrumentation.ts (yeni) — Next 14 register pattern
  - next.config.js (değişti) — withSentryConfig sarmalı
  - app/global-error.tsx (yeni) — Hata fallback UI
  - package.json (değişti) — @sentry/nextjs eklendi

GDPR güvenlik:
  - Replay'de tüm metin/input maskeli (PIN/şifre sızdırmaz)
  - Cookie/Authorization header redacted
  - Network error/offline gibi gürültüler ignore edilir
  - Sadece prod'da %10 trace rate (maliyet kontrol)

═══ 2. TENANT İZOLASYON FİX ═══

203 admin client kullanımı tarandı. 7 şüpheli sorgudan 1'i 
gerçek bug çıktı:

payments.ts:472 — payment_logs idempotency check
  Önce: .eq('sync_client_id', X)
  Sonra: .eq('sync_client_id', X).eq('business_id', businessId)

İstismar zorluğu: UUID collision gerekli (~1 milyar yıl), pratikte
imkansız. Ama defense-in-depth — düzeltildi.

Diğer 6 şüpheli sorgu false positive:
  - menu.ts (categoryId zaten doğrulanmış)
  - orders.ts/reviews.ts (review duplicate check, order_id unique)
  - tables.ts (tableId üst kısımda doğrulanmış)
  - menu.ts deleteCategory (parent zaten validate)
