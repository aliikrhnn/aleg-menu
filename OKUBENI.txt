===============================================================================

İki sorunu çözer:

  1. Bölmeden önce uygulanan indirim/bahşiş yanlış hesaplanıyordu
  2. Siparişler ekranındaki "Hesap Al" butonu kaldırıldı


[1] BÖLME + İNDİRİM/BAHŞİŞ HESAP HATASI
==========================================

ÖNCESİ:
  • Toplam ₺625 olan siparişe önce indirim+bahşiş uygulanıyor
  • PaymentModal'da görünen ödenecek: ₺643.75
  • "Bölerek Öde" basınca SplitPaymentModal açılıyor
  • UI hesabı: netTotal = order.total (625) - discount + tip = 643.75
  • Server hesabı: remainingBefore = order.total (625) - paid
  • UI 1. kişi için 321.88 gönderiyor
  • Server 625 - 0 = 625 limit görüyor → 321.88 OK ✓
  • UI 2. kişi için yine 321.88 gönderiyor
  • Server 625 - 321.88 = 303.12 limit görüyor → 321.88 RED ✗
  • Hata: "Kalan tutar ₺303.12, daha fazlası alınamaz"
  
  Yani UI ile server iki farklı total üzerinden hesap yapıyordu.

ÇÖZÜM:
  Yeni server action: applyAdjustmentsBeforeSplit
  • Bölmeye geçmeden ÖNCE order.total'a indirim/bahşiş yansıtılır
  • orders tablosuna yazılır: discount_amount, tip_amount, discount_reason
  • payment_logs'a 'adjustment' kaydı düşülür
  • Bundan sonra hem UI hem server aynı net total üzerinden çalışır

KULLANICI DENEYİMİ:
  PaymentModal'da indirim/bahşiş varken "Bölerek Öde" butonuna basınca:
  
  ┌──────────────────────────────────────┐
  │ Bölmeye geçmeden önce uyguladığın    │
  │ indirim/bahşiş siparişe yazılacak:   │
  │                                       │
  │ İndirim: ₺18.75                       │
  │ Bahşiş: ₺37.50                        │
  │ Net toplam: ₺643.75                   │
  │                                       │
  │ Devam edilsin mi?                     │
  │           [İptal]  [Tamam]            │
  └──────────────────────────────────────┘
  
  Onaylanırsa:
    • order.total = 643.75 olur
    • discount_amount = 18.75 olarak kaydedilir
    • tip_amount = 37.50 olarak kaydedilir
    • SplitPayment açılır, artık 643.75 üzerinden bölünür

SCHEMA NOTU
===========

orders tablosunda subtotal kolonu varsa applyAdjustmentsBeforeSplit
onu okur. Yoksa current order.total'ı subtotal kabul edip ondan düşer
(fallback).

İlk kez bu siparişe indirim/bahşiş uygulandığında:
  - order.total = subtotal - discount + tip
  - subtotal değişmez

Bu şekilde subtotal ham kalemler toplamı olarak kalır,
total ise net (ödenecek) tutar olur.
